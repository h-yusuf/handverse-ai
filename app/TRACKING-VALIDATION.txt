Packaged MediaPipe runtime repair (2026-11-16)
ROOT CAUSE AND OBSERVED EVIDENCE
The previous resolver call passed new URL('wasm/', document.baseURI).href.
MediaPipe 0.10.32 concatenates another '/' before the loader/binary filename.
On macOS Tauri the resulting /wasm//vision_wasm_internal.js does not match
/wasm/vision_wasm_internal.js in the embedded asset table. The SPA fallback
returned index.html. The actual packaged WKWebView probe observed HTTP 200,
text/html, 443 bytes for that malformed loader URL. A classic script that
receives HTML cannot publish self.ModuleFactory, causing the reported error.
This is a URL/asset-response failure, not evidence of a missing WASM binary or
an unsupported worker: initialization runs in the main document and the official
runtime uses classic script injection there. No worker/importScripts workaround
or vendor loader patch is needed. The same probe also found the correct model
bytes were served as text/html because .task is an unknown extension in Tauri.
